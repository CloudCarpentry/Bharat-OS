refactor: isolate filesystem client operations via ops contract (BH-FS-P1-001)

The filesystem client directly invoked `fsd_*` and `vfs_*` symbols, creating a
strong coupling between the client library and the concrete service
implementation. This prevented the clean insertion of IPC transports and
violates the boundary of a reusable client library.

This commit refactors `core/lib/fs/fs_client.c` to use a capability-aware
filesystem operations contract (`fs_client_ops_t`). The direct-call
implementation is isolated into a transitional adapter (`fs_adapter_direct.c`)
linked only where needed (e.g., in the tests and system_filesystem).
A mock IPC adapter is also provided for unit testing the forwarding layer.

- Added `core/lib/fs/fs_client_ops.h` defining the operations table.
- Removed direct service references from `core/lib/fs/fs_client.c` and
  added dynamic operations dispatch.
- Added `fs_adapter_direct.c` to provide direct `fsd_*`/`vfs_*` mapping for
  testing and current in-process service configurations.
- Added `fs_adapter_mock_ipc.c` for isolated unit testing.
- Updated `quality/tests/test_vfs_file_caps.c`, `test_vfs_ramfs.c` and others
  to register the direct adapter during host-side VFS tests.
- Handled `-ENOSYS` default return values appropriately.
- Included `test_fs_client.c` unit tests built directly via gcc for validation.

Note: The host test build environment (via CMake) currently suffers from
baseline failures due to missing source files on this branch, so the
validation of `test_fs_client.c` and the legacy VFS tests were executed manually.
